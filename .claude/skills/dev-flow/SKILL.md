# Dev-flow проекта

1. Прочитать [wiki](../../../docs/gitmark/README.md),
   [рабочий процесс](../../../docs/gitmark/agents/workflow.md) и относящийся к задаче документ.
   Проверить Git status и сохранить чужие незавершённые изменения.
2. Уточнить только недостающие решения. Исследовательский контекст, предложения и
   подтверждённые ограничения записывать в существующий документ GitMark, а не в
   параллельный план. Для новой большой задачи создать связанный `plan` в GitMark;
   разбивать задачи по скиллу `task-breakdown` после согласования границ.
3. Разработку вести в небольшой тематической ветке по
   [правилам команды](../../../docs/gitmark/team.md). Worktree допустим, если доступен,
   но не удалять чужие worktree и не переходить с незавершёнными правками без проверки.
4. Выполнить минимальное изменение, обновить каноническую документацию и проверить
   поведением или строгой сборкой wiki. Запускать `gitmark lint --strict`, обновлять индекс
   и собирать MkDocs после правок KB. Человеку передать diff, результаты проверки и
   незакрытые ограничения; включение через PR и review по правилам команды.

CI проекта пока проверяет wiki в job `checks`; деплой, контейнерные сервисы,
Codex-review и автоматические исправления @claude не настроены. Проверять
актуальные команды в [README](../../../README.md) и конфигурации CI, не считать
возможности шаблона внедрёнными автоматически.
