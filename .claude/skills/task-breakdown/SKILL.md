# Декомпозиция задачи

1. Прочитать задачу в [каноническом списке](../../../docs/gitmark/README.md#ближайшие-задачи)
   и связанную постановку. До разделения проверить границы, решения и неизвестное;
   недостающие существенные решения вернуть на обсуждение.
2. Для каждого шага указать цель, затрагиваемые файлы, порядок/зависимости,
   принятое решение, **критерий завершения (DoD)** и **воспроизводимую проверку**.
   Не создавать шаги и каталоги ради неопределённого будущего.
3. Небольшую задачу оставить пунктом канонического списка. Для большой согласованной
   разработки оформить отдельный исторический `plan` в `docs/gitmark/plans/`
   со ссылкой из списка задач; создать `README.md` для нового каталога.
4. Получить подтверждение человека для существенного изменения объёма.
   Реализацию вести по [процессу команды](../../../docs/gitmark/team.md);
   выводы и новые решения возвращать в живую документацию, не объявляя план
   реализованным только потому, что список шагов закрыт.
